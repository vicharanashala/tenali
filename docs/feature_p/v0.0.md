# Feature P: Version 0.0 - Concept & Requirements
**Author**: Priyanshu Kumar (@priyanshu7725)

## Purpose
The objective of Feature P (Prerequisite Auto-Routing & Warmups) is to introduce a mastery-based learning mechanism within the platform. The system should detect when a student is struggling and proactively intervene, rather than allowing continuous failure or artificially lowering the difficulty of the active quiz.

## Key Decisions
- **Intervention Metric: Consecutive vs. Sliding Window**: 
  - Originally, the requirements called for an intervention to trigger after three consecutive incorrect answers.
  - During conceptual design, this was revised to a sliding window of three incorrect answers out of the last four submissions (3/4).
  - *Rationale*: A single correct answer by guessing or random chance should not reset the struggle counter if the overall pattern indicates persistent conceptual difficulty. A sliding window of 4 is a more robust metric for detecting genuine poor performance.
- **Intervention Workflow**: Upon triggering, the active quiz is paused and a prerequisite warmup overlay is presented to initiate a targeted warmup. A prerequisite is not always simpler—it may just be more foundational.
- **State Preservation**: The application must retain the context of the user's current session (topic, difficulty, score) to seamlessly route them back to their origin point once the warmup is concluded.

## Implementation
- Plan client-side state variables (`historyWindowRef`) to track the sliding window of submissions.
- Map complex topics (like Quadratics) to their prerequisite dependencies via a server-side JSON file.
- Implement the prerequisite warmup overlay as a modal overlay in the React tree.
