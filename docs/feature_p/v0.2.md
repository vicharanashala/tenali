# Feature P: Version 0.2 - Dynamic Prerequisite Warmups & Schema Normalization
**Author**: Priyanshu Kumar (@priyanshu7725)

## Purpose
Transition from static prototype warmups to live, topic-aware warmups fetched dynamically from the backend prerequisite tree.

## Key Decisions
- **Prerequisite Fetching & Traversal**:
  - Implemented the `GET /api/prerequisites/:topic` endpoint on the server loading from `server/prerequisites.json`.
  - Implemented level-by-level (BFS) client traversal to resolve multiple prerequisites dynamically, incorporating caching, cycle detection, and max depth limits. **(BFS traversal was implemented in v0.2 but never deployed — v0.3 replaced this with direct-parent-only lookup before the v0.2 work reached production. Cycle detection is still performed server-side at startup, but client-side traversal is not used.)**
- **Warmup Compatibility Whitelist**:
  - Established `WARMUP_SUPPORTED_TOPICS` whitelist. Only topics that accept string/numeric answers via `/check` are whitelisted for warmup queries, filtering out unsupported complex UI formats.
- **Normalizing Question Prompts**:
  - Created `getWarmupPrompt` to normalize heterogeneous question JSON formats into readable prompt strings.
- **Session History Guard**:
  - Used `sessionWarmupTopicsRef` to cache completed warmups and avoid repeating identical topics within a single quiz session.

## Implementation
- Added server routes for fetching dependencies.
- Added prompt normalization layer and live validation logic calling prerequisite `/check` endpoints.
- Integrated `sessionWarmupTopicsRef` to route past completed nodes.

## Retrospective
Although the recursive prerequisite traversal worked technically, it assumed the system could accurately infer the student's missing concept from the prerequisite graph alone.

Later design discussions concluded that prerequisite graphs are only approximations of student understanding.

This architecture was therefore replaced in v0.3 with a student-controlled prerequisite picker.
