# Feature P: Version 0.1 - Prototype Struggle Detection & Warmup Overlay
**Author**: Priyanshu Kumar (@priyanshu7725)

## Purpose
Introduce the client-side struggle detection engine and the baseline state-preservation framework for warmups in a prototype environment.

## Key Decisions
- **Prototype Scope**: This version intentionally uses hardcoded warmup content to validate the interaction flow and state preservation before introducing dynamic prerequisite resolution.
- **Struggle Window Tracking**: Implemented the sliding window logic tracking the last 4 submissions. If 3 or more are incorrect, the struggle state is activated.
- **State Snapshotting**: Before launching the warmup, the main quiz states (`questionNumber`, `score`, `results`) are snapshotted (`frozenQuizState`) to allow seamless return.
- **Baseline Cooldown**: Configured a `cooldownCounter` of 4 questions post-warmup completion. This bypasses struggle checks, allowing the sliding window to fully rotate before re-checking for poor performance.

## Implementation
- Implemented sliding-window state tracking in `client/src/App.jsx`. (Originally here, but later extracted to a reusable hook at `client/src/hooks/useWarmupIntervention.jsx` as part of v1.0 client-side cleanup.)
- Designed a prototype warmup modal rendering 3 hardcoded single-digit addition questions (`WARMUP_QUESTIONS_V01`) to validate submission and completion states.
- Handled state restoration upon final warmup question completion.
