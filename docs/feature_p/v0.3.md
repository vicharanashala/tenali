# Feature P: Version 0.3 - Prerequisite Picker, Cooldowns & Local Database Integration
**Author**: Priyanshu Kumar (@priyanshu7725)

## Purpose
Introduce student choice via a prerequisite selection UI, refine intervention cooldowns, integrate the Hesitation Monitor, and resolve local database startup issues.

## Key Decisions
- **Three-Tier Escalation Path**:
  - *Trigger 1*: Auto-routes directly to the recommended prerequisite warmup.
  - *Trigger 2*: Triggers the Prerequisite Picker modal to let the student select from up to 3 options.
  - *Trigger 3+*: Displays the Learning Recommendation panel suggesting deep concept reviews.
- **Picker Design Refinements**:
  - *Unsupported Formats*: Shown in the Prerequisite Picker but the button is disabled, the chip is dimmed (`var(--clr-dim, #888)`), and the label is `[Practice coming soon]` (renamed from `[Warmup unavailable]` in pre-v1.0 design review to be generic across all prereq learning surfaces, not just warmups).
  - *Completed Topics (this session)*: Shown in the Picker with a ✓ indicator next to the topic name. The button remains **enabled** so the student can re-run a warmup if they want to revisit material they may have missed the first time. Tracked via `sessionWarmupTopicsRef` (Set of completed prereq topics in the current session), but only used for the visual indicator — not to disable the action.
- **Dual Cooldown Controls**:
  - Bypasses struggle checks for 4 questions (`cooldownRef = 4`).
  - Suppresses hesitation-based prerequisite suggestions (the Hesitation Monitor) for the next two submitted questions following a completed warmup (`hesitationCooldownRef = 2`).
- **Telemetry Cleanup**:
  - Removed prototype analytics collection code. The feature was intentionally scoped to avoid collecting analytics before a product consumer (teacher dashboard, parent dashboard, or adaptive analytics) existed.

## Implementation
- Replaced recursive BFS traversal with direct prerequisite lookup and the Prerequisite Picker overlay.
- Added `hesitationCooldownRef` decrement logic on answer submissions.
- Removed analytics telemetry routes and client logs.

## Appendix: Implementation Notes
- **Local DB Connection Timeout**: During integration testing, we resolved a startup database connection crash by increasing Mongoose `serverSelectionTimeoutMS` from 4000 to 10000 inside `server/auth.js`. This prevents connection timeouts caused by the synchronous `bcryptjs` password hashing routine blocking the Node.js event loop during startup.
